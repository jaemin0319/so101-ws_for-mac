# 2단계: 리더→팔로워 추종(macOS)

공식 `lerobot-teleoperate`를 래퍼(`02_teleop/run.sh`)로 실행합니다.

**전제 조건**
- [SETUP.md](SETUP.md)를 마쳤습니다.
- 두 팔의 probe가 6/6이고, 보정 파일 상태가 `match`입니다.
- 로봇 옆에 사람이 있습니다. 팔로워를 받칠 수 있고, 팔로워 전원을 바로 끊을 수 있습니다.

```bash
cd ~/so101-ws_for-mac
```

## 0. 맥 준비

- **전원 어댑터를 연결하고 덮개를 닫지 않습니다.**
  - 실행 중에는 래퍼가 `caffeinate`로 유휴 절전을 막습니다.
  - 덮개를 닫아서 생기는 절전은 막지 못합니다. 절전에 들어가면 USB 통신이 멈추고, 팔로워가 마지막 자세에서 토크를 유지할 수 있습니다.
- USB 허브와 케이블이 빠지지 않게 고정합니다.
- 녹화(`03_dataset/record.sh`)와 동시에 실행하지 않습니다. 녹화도 같은 두 포트를 씁니다.

## 1. 명령 확인 (포트를 열지 않음)

```bash
./02_teleop/run.sh --dry-run
```

- **화면 내용**: 실행할 공식 명령과 `[OK] 공식 TeleoperateConfig 파싱`이 나옵니다.
- **실패하면**: `[FAIL]` 메시지의 설정 항목을 고칩니다. 포트·ID 문제라면 `./01_setup/ports.sh`를 다시 실행합니다.

## 2. 30초 첫 시험

```bash
./02_teleop/run.sh --time-s 30
```

**래퍼가 공식 명령 전에 하는 점검**(모터에 쓰지 않음)
- 포트, 같은 장치 여부, USB 지문
- 보정 파일
- 6개 모터의 응답과 펌웨어
- 보정 파일과 모터 레지스터의 일치

하나라도 맞지 않으면 시작하지 않습니다. 자동으로 다시 보정하지도 않습니다.

**시작 절차**
1. **자세 차이 표**(리더 − 팔로워)를 봅니다.
2. 리더를 팔로워 자세 가까이 맞춥니다.
3. 체크리스트를 확인하고 **Enter**를 누르면 시작합니다(취소: `q` 입력 후 Enter 또는 Ctrl+C).
4. 관절을 하나씩 작게 움직여 봅니다. gripper를 열고 닫아 봅니다.
5. 시간 상한에 도달하면 공식 코드가 토크를 해제합니다. **팔로워가 처질 수 있으니 받쳐 둡니다.**

## 3. 종료(언제나 이 순서)

1. 리더를 쉬는 자세로 천천히 옮깁니다.
2. 팔로워를 손으로 받칩니다.
3. `Ctrl+C`를 누릅니다.
4. 마지막 `== 종료 요약`에서 다음을 확인합니다.
   - `leader/follower 토크 해제 재시도: 성공`
   - 추종 루프 구간(초)과 Hz 중앙값
   - 절전 방지 종료(`'ended': True`)

**토크 해제가 `실패`·`확인 불가`이거나(종료 코드 3) 응답이 없으면**
1. 팔로워를 받친 채 **팔로워 전원을 끕니다.**
2. USB와 전원을 확인합니다.
3. `./01_setup/probe.sh both`를 실행합니다.
4. 같은 명령을 다시 실행합니다.

**종료 처리 방식**
- Ctrl+C·SIGTERM·터미널 닫힘(SIGHUP)이면 공식 프로세스에 SIGINT를 한 번만 전달합니다. 공식 정리(disconnect)가 끝나면 래퍼가 양팔 토크 해제를 각각 다시 시도합니다.
- 래퍼가 강제 종료되면 macOS 런처가 이를 감지해 공식 프로세스를 정리합니다.

**한계**
- 모든 프로세스가 강제 종료(SIGKILL)되거나 USB가 끊기면, 소프트웨어로 토크 해제를 보장할 수 없습니다.
- 최종 수단은 전원 차단입니다.

## 4. 3분 연속 시험·재실행

```bash
./02_teleop/run.sh --time-s 240     # 180초가 지나면 쉬는 자세 → 받침 → Ctrl+C
./02_teleop/run.sh --time-s 30      # 종료 후 같은 명령으로 재실행 확인
```

**기록 확인**: `logs/runs.jsonl`의 마지막 teleop 항목에서 다음 값을 봅니다.

| 항목 | 의미 |
|---|---|
| `teleop_loop.loop_span_s` | 첫 루프 출력부터 마지막 루프 출력까지(초). **3분 판정 기준** |
| `hz_median`, `loop_ms_p95` | 실제 루프 주기 |
| `exit_code`, `user_interrupt` | 종료 방식 |
| `cleanup.*.status` | 종료 후 토크 해제 재시도 결과 |
| `keep_awake` | 절전 방지 시작·종료 |

**판정 원칙**
- 프로세스가 3분 동안 떠 있었다는 것(`duration_s`)만으로 3분 추종 성공으로 판정하지 않습니다.
- 추종 오차를 재지 않았으면 "관찰 기반"으로 적습니다.

**시험할 것**: VS Code 창을 앞에 두었을 때와 뒤에 두었을 때의 Hz를 각각 기록합니다(macOS 백그라운드 동작 확인).
