# 1단계: 설치와 초기 세팅(macOS, Apple Silicon)

터미널 하나에서 위에서부터 순서대로 진행합니다. 모든 명령은 작업공간에서 실행합니다.

```bash
cd ~/so101-ws_for-mac
```

- 모터를 움직이거나 모터에 쓰는 단계(모터 ID 설정·보정)는 **사람이 로봇 옆에서 직접** 실행합니다.
  - 팔을 받칠 수 있어야 합니다.
  - 팔로워 전원을 바로 끊을 수 있어야 합니다.
- Linux(Ubuntu) 절차는 [REPRODUCE.md](REPRODUCE.md)를 보세요.

---

## 1. 설치 (로봇 불필요)

**실행**

```bash
./01_setup/install.sh
./01_setup/doctor.sh
```

**설치가 하는 일**: 모든 파일은 작업공간 안에만 둡니다.

| 위치 | 내용 |
|---|---|
| `.tools/uv` | uv 0.12.23. 공식 체크섬으로 검증합니다 |
| `.tools/python` | Python 3.12.15(uv managed) |
| `external/lerobot` | LeRobot v0.6.1 고정 SHA 원본 |
| `.venv` | `lock/macos-arm64/uv.lock` 그대로 설치합니다 |

셸 설정, 기존 Python, Homebrew는 바꾸지 않습니다.

**다음으로 가는 조건**
- `doctor.sh`의 마지막 줄이 `결과: FAIL 0`입니다.
- 종료 코드는 0(OK) 또는 2(WARN만)입니다.
- 이 맥에서 알려진 WARN은 1개입니다: "cv2와 av가 같은 FFmpeg 장치 라이브러리를 각각 포함".
  - 설명은 [macos_setup_report.md](macos_setup_report.md)에 있습니다.
  - 데이터셋 단계에서 실카메라로 확인합니다.

**실패하면**

| 증상 | 조치 |
|---|---|
| 다운로드 오류 | 그대로 다시 실행합니다. 받은 파일은 `.cache/uv`에서 재사용합니다 |
| 파일 손상 의심(doctor의 "고정 SHA 소스와 다름" 등) | `./01_setup/install.sh --repair` |
| `.venv`의 Python이 다름 | `./01_setup/install.sh --reset-venv`. 기존 `.venv`는 지우지 않고 `.venv.broken-<시각>`으로 옮깁니다 |
| `git` 오류 | Xcode Command Line Tools가 필요합니다: `xcode-select --install`(사용자가 직접 실행) |
| 공간 부족 | 약 4 GB 여유가 필요합니다(설치 후 실사용 약 2.2 GB). 공간을 확보한 뒤 다시 실행합니다 |

## 2. USB 포트 지정 (모터 전원 OFF, USB만)

**준비**
- 리더·팔로워 팔의 **모터 외부 전원(어댑터)을 모두 끕니다.**
- MacBook Air는 USB-C 단자뿐이므로, 보드가 USB-A라면 허브나 어댑터를 준비합니다.
- 실행 중 빠지지 않게 허브와 케이블을 고정합니다.

**실행**

```bash
./01_setup/ports.sh
```

**화면 안내 순서**

1. 두 보드의 USB를 모두 뽑고 Enter를 누릅니다.
2. **리더** 보드의 USB만 연결하고 Enter를 누릅니다. 새로 나타난 장치를 리더로 표시합니다.
3. **팔로워** 보드의 USB를 연결하고 Enter를 누릅니다. 새로 나타난 장치를 팔로워로 표시합니다.
4. 각 팔의 **장치 ID**를 입력합니다. 예: `so101_leader_a`, `so101_follower_a`.
   - 장치 ID는 물리 팔에 붙인 라벨과 같은 이름이며, 보정 파일 이름이 됩니다.
   - **모터 ID 1~6과 다릅니다.**
   - 이미 저장된 ID가 있으면 Enter로 유지합니다.
5. 바뀌는 내용(diff)을 확인하고 `yes`를 입력합니다.
   - `configs/robot.local.yaml`에 저장됩니다.
   - 기존 파일이 있으면 `robot.local.yaml.bak-<시각>`으로 백업합니다.

**마법사의 동작 원칙**
- 포트를 **열지 않습니다.** 장치 목록만 읽습니다.
- 찾은 장치가 여러 개면 번호로 고르게 합니다. 발견 순서로 역할을 추측하지 않습니다.
- `/dev/tty.X`와 `/dev/cu.X`는 같은 보드로 셉니다. `cu.X`를 저장합니다.
- Bluetooth 같은 비USB 장치는 후보에서 뺍니다.
- 보드의 USB serial이 고유하면 serial로 보드를 확인합니다. 다른 단자로 옮겨도 같은 보드로 확인됩니다.
- serial이 없거나 두 보드가 같으면 **USB 위치**로 확인합니다. 이 경우 앞으로 **항상 같은 단자와 허브 포트**에 꽂아야 합니다.
- 두 정보가 모두 없으면 자동 저장을 거부합니다.
- 취소(Ctrl+C·`q`·`yes`가 아닌 답)나 오류가 나면 기존 설정을 그대로 둡니다.

**확인**

```bash
./01_setup/ports.sh --list            # 현재 장치와 설정 매핑·USB 지문 대조(읽기 전용)
./01_setup/doctor.sh --hardware       # 포트·권한·점유·USB 지문·보정 파일(포트를 열지 않음)
```

**다음으로 가는 조건**
- `doctor.sh --hardware`의 FAIL이 0입니다.
- 보정 전에는 "보정 파일 없음" WARN이 정상입니다.

**실패하면**

| 증상 | 조치 |
|---|---|
| 새 장치가 보이지 않음 | 데이터 전송이 되는 케이블인지, 허브·어댑터에 꽂혔는지 확인합니다. 화면에 USB 장치 트리(ioreg)가 함께 나옵니다 |
| USB만으로는 보이지 않는 보드 | 서보 전원이 있어야 보이는 보드일 수 있습니다. 아래 3번의 전압·극성 확인을 먼저 하고, 전원을 넣은 뒤 다시 실행합니다 |
| 장치 트리에는 있는데 시리얼 장치가 없음 | 보드 칩에 맞는 드라이버가 필요할 수 있습니다. 설치는 사용자가 판단합니다(이 스크립트는 드라이버를 설치하지 않음) |
| 나중에 "USB 지문이 기록과 다름" | 다른 보드이거나, serial 없는 보드를 다른 단자에 꽂은 경우입니다. 역할을 추측하지 말고 `./01_setup/ports.sh`를 다시 실행합니다. 기존 장치 ID는 Enter로 유지됩니다 |
| 공식 방식으로 다시 확인하고 싶음 | `./01_setup/ports.sh --find-port`(공식 `lerobot-find-port`, USB를 뽑는 방식) |

## 3. 실물 확인 → 전원 연결

전원을 넣기 전에 [HARDWARE.md](HARDWARE.md) 2절 표를 채웁니다.

- 모터 라벨 전압
- 어댑터 출력 정격과 극성
- 보드 모델과 모드(점퍼)
- 배선(보드 → 1번 → … → 6번 데이지체인)

표를 확인한 뒤 **각 팔에 맞는 어댑터**를 연결합니다. 리더와 팔로워는 각각 별도 보드, 별도 전원을 씁니다.

## 4. 모터 확인 (읽기 전용)

**실행**

```bash
./01_setup/probe.sh follower
./01_setup/probe.sh leader
```

**출력 내용**: 관절별 ID, 모델, 펌웨어, 현재 위치, 토크, 보정 레지스터를 읽어서 보여 줍니다. 모터에는 아무것도 쓰지 않습니다.

**다음으로 가는 조건**
- `응답·모델 일치: 6/6`이면 5번(모터 ID 설정)을 **건너뜁니다.**

**실패하면**
- 다음 순서로 확인합니다: 전원 → 케이블(보드↔1번, 체인) → 보드 모드 → 포트 → baud.
- baud 확인은 `./01_setup/probe.sh follower --scan`입니다(공식 `scan_port`, 쓰기 없음).
- 그래도 특정 ID가 없거나 겹칠 때만 5번으로 갑니다.
- EEPROM 초기화나 펌웨어 갱신은 하지 않습니다.

## 5. (필요한 팔만) 모터 ID·baud 설정

probe에서 ID 누락이나 충돌이 확인된 팔에만 실행합니다.

**모터 ID**: 베이스부터 차례로

| 관절 | 모터 ID |
|---|---|
| shoulder_pan | 1 |
| shoulder_lift | 2 |
| elbow_flex | 3 |
| wrist_flex | 4 |
| wrist_roll | 5 |
| gripper | 6 |

**실행**

```bash
./01_setup/motors.sh follower     # 또는 leader
```

1. 래퍼가 포트와 USB 지문을 확인하고 `yes`를 받습니다.
2. 공식 `lerobot-setup-motors`가 **gripper(6)부터** 모터를 하나씩 안내합니다.
3. 안내된 모터 **하나만** 보드에 연결하고 Enter를 누릅니다.
   - 그 모터에서 다음 모터로 이어지는 케이블도 빼서, 버스에 그 모터 하나만 남깁니다.
   - **케이블을 바꾸기 전에는 반드시 모터 전원을 끕니다.**
   - 조립된 팔에서도 할 수 있습니다. 보드→1번 케이블이나 비어 있는 커넥터를 해당 모터로 옮겨 연결합니다.
4. 이미 올바르게 응답한 팔에는 실행하지 않습니다(불필요한 재설정 금지).

## 6. 보정

보정 파일이 없거나 probe에서 "보정 파일 상태: mismatch"일 때 실행합니다.

**실행**

```bash
./01_setup/calibrate.sh follower     # 팔로워를 손으로 받친 상태로
./01_setup/calibrate.sh leader
./01_setup/probe.sh both             # '보정 파일 상태: match' 확인
```

**공식 순서**(v0.6.1)
1. 파일이 이미 있으면 다음 중 하나를 고릅니다.
   - Enter: 파일 값을 모터에 기록합니다.
   - `c`: 다시 보정합니다.
2. 모든 관절을 **가동 범위의 가운데**에 두고 Enter를 누릅니다.
3. wrist_roll을 뺀 관절을 끝에서 끝까지 움직이고 Enter를 누릅니다.

**가운데 자세가 중요한 이유**: Enter를 누른 순간 각 관절의 현재 위치가 2047(0~4095의 가운데)로 정해집니다. 관절은 그 자세에서 한쪽으로 약 2047(약 180°) 넘게 움직이면 0↔4095로 넘어갑니다.
- 2번에서는 관절마다 양 끝까지 한 번 움직여 보고, **그 중간에 둔 뒤** Enter를 누릅니다. 특히 shoulder_lift·elbow_flex·wrist_flex를 신경 씁니다.
- 가동 범위를 기록하는 동안 표의 MIN·MAX를 봅니다. wrist_roll이 아닌 관절이 **MIN 0 근처나 MAX 4095 근처로 갑자기 튀면** 넘어간 것입니다. 이때는 Enter를 누르지 말고 `Ctrl+C`로 중단한 뒤 처음부터 다시 합니다(중단하면 저장되지 않음).
- 넘어간 상태로 저장되면 래퍼가 보정 파일 검사에서 FAIL을 내고, 텔레옵·녹화를 시작하지 않습니다.

**보정 파일 위치**(공식 형식, Git 제외)
- `calibration/robots/so_follower/<팔로워 id>.json`
- `calibration/teleoperators/so_leader/<리더 id>.json`

**지킬 것**
- 다른 팔의 보정 파일을 복사하지 않습니다.
- 백업 방법은 [HARDWARE.md](HARDWARE.md) 5절을 봅니다.
